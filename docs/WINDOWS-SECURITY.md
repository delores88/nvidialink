# Windows installation and link security

The current installer is unsigned. SmartScreen reputation, antivirus decisions and network firewall rules are separate mechanisms. A successful Marketplace static review does not disable Windows protection or establish operating-system publisher signing. RTXBridge does not turn off SmartScreen, Defender or firewall profiles, or remove download provenance.

For a future signed release, the proposed option is Microsoft Azure Artifact Signing Basic with a Public Trust profile. Microsoft's current published price is $9.99 per month for 5,000 signatures, then $0.005 per additional signature. It requires a paid Azure subscription, appropriate Microsoft Entra roles and validation of the actual legal organization or eligible individual. DeloresAI's eligibility has not been established. This is a proposal only: no purchase, account enrollment, identity submission, signing key or certificate import has been performed. [Pricing](https://learn.microsoft.com/en-us/azure/artifact-signing/how-to-change-sku), [setup requirements](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart), [service FAQ](https://learn.microsoft.com/en-us/azure/artifact-signing/faq).

A conventional organization-validated certificate is an alternative. Microsoft's comparison gives indicative costs of $150–300 per year and requires hardware-token or HSM key custody. EV certificates cost more and no longer provide an automatic SmartScreen bypass. New signed files may still need reputation to build. A chosen signing method must be integrated before final binary hashes, package audits and Marketplace review; published accepted files must not be silently replaced. [Microsoft's code-signing comparison](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options).

The link client initiates QUIC connections and uses an ephemeral UDP socket for replies. Eliminating that socket would break the transport. No Windows TCP approval listener is required: the phone page is served by the Spark. Normal outbound traffic and its solicited replies do not justify a broad inbound exception. An enabled explicit block rule can override an allow rule; adding another allow rule is not a reliable repair. [Microsoft's firewall rules and precedence](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules).

The application reads effective firewall policy only when a link connection fails. It requires a known active profile, exact executable path and a matching enabled block before reporting a firewall block. Missing evidence remains unknown. On the observed second PC no matching application rule was found; the immediate pairing failure was consistent with the client clock check and did not establish a need for an inbound rule. No automatic UAC repair or Public-profile rule is added. If a future deployment demonstrates a genuine need for unsolicited Private-LAN traffic, a separate owner-confirmed elevated step must scope its rule to that exact verified executable and the Private profile; it must preserve Public policy and disclose conflicting block rules.
