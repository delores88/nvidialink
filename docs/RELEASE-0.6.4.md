# RTXBridge 0.6.4

This release carries the remaining board-1833 work above the already published and accepted 0.6.3. The 0.6.2 and 0.6.3 tags, installer files and Marketplace records remain unchanged. The owner explicitly selected 0.6.4 for these additional fixes.

Pairing diagnosis found the new PC's tickets being cancelled immediately, before phone approval. Its clock was slightly behind the Spark's. The old client rejected a fresh 300-second ticket when its clock was even one second behind the issuer. The client now permits a five-second margin in its future-timestamp sanity check. Already-expired tickets still fail; the Spark's 300-second expiry, endpoint identity checks, authenticated acceptance and phone approval are unchanged. Fixed error codes distinguish clock disagreement, connection failure, approval expiry or denial, verification failure and local-save failure. The desktop projects recognized codes to fixed messages without exposing ticket contents or raw subprocess diagnostics.

The client already initiates its connections. Its QUIC UDP socket is still required for replies; no Windows TCP listener is added. UDP 47831 is the Spark's link endpoint; TCP 7437 serves its phone approval page. A timeout alone is not a firewall diagnosis. A bounded, read-only Windows query reports a block only when enabled effective policy has a matching, active-profile block for the exact link executable. No firewall or network-profile changes are made, and no Public-profile exception is added. The observed second PC had no matching application rule. An unsolicited inbound allow rule is not required for this correction and would not override an explicit block. Signing options are proposed separately in [Windows security](WINDOWS-SECURITY.md); no certificate or service was purchased.

The Windows host-memory patch is ported from exact first-party commit `52e05b8c5de7444be6383072cd67f5c815966533`. It observes Windows physical memory through the device's pinned SSH profile and caches it. The card shows host memory, and the existing detail facts distinguish the smaller amount available to WSL jobs. Resource admission and WSL allocation are unchanged. AntonPC independently reported 274,704,207,872 physical bytes, or 255.84 GiB, which the existing model rounds to 256 GB.

Local Windows form-factor observation uses native battery status and bounded chassis information. A desktop appears as “This PC” with the existing desktop icon; a laptop retains its name and icon. Unknown evidence keeps the existing display. The local-device identity, map role, controls, layout, styling and other UI wording are unchanged. These are the two UI exceptions explicitly authorized in board 1833.

Source suites, synthetic pairing tests, actual hardware observations, package audits, GitHub publication, Marketplace static admission and an installed updater cycle are separate evidence layers. Operation receipts identify which checks actually ran. No second-PC phone approval, new owner pairing or hotspot acceptance is inferred from source tests.
