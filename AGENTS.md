Local cargo builds/tests must run through `python -I D:/PhaseForge-claude/scripts/buildlock.py -- cargo ...`. Keep build artifacts on C: (D: has limited free space). Do not start unrestricted Spark jobs: use separate sparkdev resources and caps. Never sudo.

Receipt claims must distinguish unit tests, real Spark runs, installed Windows behavior, remote hotspot verification and Marketplace admission. Never fabricate a Claude Code run by setting `--client claude` yourself.

Offload Linux-capable builds, tests, rendering, media conversion and compute to Spark by default. First use `sparkdev --client codex --json devices` and `status --all`, then `sparkdev --client codex --json run DIR --where auto --detach --request-id RETAINED_ID -- COMMAND ARGS`. Retain the returned job ID, poll `wait JOB --timeout 20`, and consume `logs JOB --since OFFSET` using its next byte offset. Retry an uncertain submission with the same request ID instead of duplicating it. Keep Windows-only jobs on the laptop through the unchanged build gate; an unavailable Spark scheduler is a reported blocker, not permission to bypass it silently. Python defaults to the `python` runtime; request `--runtime cuda` for GPU Python. Direct `ffmpeg` and `blender` commands infer `cuda`; the workload must still select supported GPU operations.

In 0.5.0, Spark batch jobs automatically return changed/new project files and `/sparkdev-output` files. Keep polling while `state` is `returning`, then inspect the terminal workload exit code and `returned` receipts. No fetch command or manual file copying is needed. `outputs JOB` is optional metadata inspection; never encode binary results into logs. Newer laptop edits are preserved with `.spark-JOBID` conflict copies. Original files replaced safely may leave hidden `.name.spark-original-JOB-UUID` backups; preserve them. Use `--no-return` only when results should deliberately stay on Spark. See docs/CLI.md for quotas, expiry and retry behavior.

Prepare locked dependencies before offline execution. For system libraries/fonts, use the documented scratch-project `/sparkdev-system.py lock` recipe, copy the returned exact `sparkdev-system.lock` into the target project and run `prepare` with the matching runtime. Never run host apt/sudo or invent package versions/digests. See docs/CLI.md and docs/MCP.md. Candidate source checks do not establish physical Spark, installed Windows or Marketplace acceptance.
